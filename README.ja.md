## 概要

**minidb** は、リレーショナルデータベースの低レイヤ（ストレージ・インデックス・トランザクション）を、PostgreSQL のオンディスク構造を参考に第一原理から再実装する学習プロジェクトです。

目標は本番用データベースを作ることではなく、データベースが **バイト単位でどう動くか** を理解することにあります。ページがどう配置され、可変長レコードが固定長ページにどう詰め込まれ、MVCC / WAL のメタデータがストレージ形式にどう組み込まれるか——これらを実装を通して体得します。

**なぜ作るのか**

- データベースの低レイヤ（ストレージ / インデックス / トランザクション）を、読むだけでなく実装して理解する。
- バイト・ビット単位のエンコードをすべて手書きし（ORM やシリアライズライブラリを使わない）、フォーマットを体に落とす。
- Go によるシステムレベルのエンジニアリングを示すポートフォリオ。

## 設計のポイント

現在の実装の中心はストレージエンジンです。いくつかの意図的な設計判断:

### Slotted Page（8KB）

各ページは固定 **8KB** のブロックで、**Slotted Page** 構造を採用しています。これにより、可変長タプルを固定長ページ内で扱いながら、物理的な格納位置が動いても **スロット ID を固定** したまま保てます。ページサイズは PostgreSQL のデフォルトに合わせています。

### 双方向の伸長

ページ内では、**スロットディレクトリはヘッダー末尾から前方へ**、**タプルデータはページ末尾から後方へ** 伸びます。`pd_lower` と `pd_upper` が両者の境界を管理し、両者が交差する時点でページが満杯になります。

```
┌────────────┬──────────────┬───────────────┬──────────────┐
│ PageHeader │ Slot dir  →  │  free space   │  ←  Tuples    │
│  (24 B)    │ (前方へ)      │               │ (後方へ)       │
└────────────┴──────────────┴───────────────┴──────────────┘
             ^ pd_lower                      ^ pd_upper
```

### 手書きのスロットエントリ

各 `SlotEntry` は **4 バイト** に詰め込まれます——15 ビットのオフセット、15 ビットの長さ、2 ビットのステータスフラグ（`UNUSED / NORMAL / DELETED / REDIRECT`）を、シリアライズライブラリではなく明示的なマスク・シフト演算で組み立てます。

### MVCC / WAL 対応ヘッダー

24 バイトのページヘッダーは PostgreSQL 由来のフィールド——`pd_lsn`（WAL）、`pd_checksum`、`pd_lower` / `pd_upper`、`pd_prune_xid`（MVCC / VACUUM）——を確保し、タプルヘッダーはトランザクション・可視性のメタデータを持ちます。トランザクション層・リカバリ層を作る前から、フォーマットがそれらに対応できる形になっています。

### ゼロコピーなアクセス

ヘッダーやエントリは、基盤のページバッファを直接ラップする固定長配列ポインタ（`*[N]byte`）としてアクセスし、ビッグエンディアンの getter / setter で読み書きします——フィールドごとのコピーは発生しません。

バイトレイアウトの詳細は [docs/design/storage/Physical-Storage-Design.ja.md](docs/design/storage/Physical-Storage-Design.ja.md) とページ配置図 [docs/design/storage/assets/Slotted-Page.png](docs/design/storage/assets/Slotted-Page.png) を参照してください。

## 動かし方

**Go 1.26 以上** が必要です。

```bash
git clone https://github.com/ailuruschen-bit/mini_db.git
cd mini_db
go build ./...
go run ./cmd/server   # エントリポイント（現状スタブ）
```
