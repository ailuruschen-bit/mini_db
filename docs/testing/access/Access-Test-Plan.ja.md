# アクセスモジュール テスト計画

> 言語: [English](Access-Test-Plan.md) | **日本語**

`internal/access` モジュール — バッファプールの上のアクセスメソッドのテスト計画: `heap` パッケージ（ヒープファイルのアクセスメソッド、ページをタプルに変える）と `nbtree` パッケージ（B+Tree インデックス、key を TID に対応づける）。*どう書くか*（フレームワーク、`-race`、カバレッジ）は [テスト規約](../Test-Conventions.ja.md) にあり、本書はコンポーネントごとに *何をカバーするか* を列挙する。

---

## 0. 共有ヘルパー

**heap:**

- `newHeap(poolSize)` — 一時ディレクトリの実バッファプール + ディスクファイル上のヒープ。
- `payload(seed, size)` — 指定サイズの、区別・検証可能なタプル。
- `initPage()` — フェイク状態を組むための整形済み空ページ。
- `fakePool` — heap が依存する消費者側インタフェース `pager` を実装し、`FetchPage`/`NewPage` をオンデマンドで失敗させる。heap の I/O エラー経路を決定論的に駆動するため。

**nbtree:**

- `newTree(poolSize)` — 一時ディレクトリの実バッファプール + ディスクファイル上の B+Tree（ブラックボックス、本番容量）。
- `fakePool` — 追い出しをしないインメモリの `pager`（木全体が常駐）。I/O エラー経路のため `failFetch`/`failNew` を注入可能（ホワイトボックス）。
- `smallCaps(leaf, internal)` — テストの間だけノード容量を縮小し、わずかな key で葉分裂・内部分裂・root 成長を強制する。
- `newLeaf()` / `newInternal()` — 空フレーム上の整形済み空ノード; `tid(seed)` — 識別可能な TID。

## 1. Heap（`heap_test.go`、ブラックボックス `heap_test`）

`TID = {Page, Slot}` はタプルの物理アドレス。v1 の操作: Insert / Get / Scan（削除・更新は MVCC/トランザクション層待ち）。タプルのバイトは heap にとって不透明。

- [x] **往復:** Insert 後に Get が同じバイトを返す。
- [x] **ページをまたぐ:** 十分大きいタプルが新しいページへあふれ、そのすべてが id で読み戻せる。
- [x] **Scan:** すべてのタプルをちょうど一度ずつ、ページをまたぎ、追い出しを通して（プールがページ数より小さい）訪れる。
- [x] **Scan の早期停止:** コールバックのエラーがスキャンを中断し、外へ伝播する。
- [x] **Get の境界:** 範囲外スロットを拒否; 存在しないページを拒否。
- [x] **大きすぎる Insert:** 空ページに収まらないタプルは、落とさず拒否する。
- [x] **永続化:** タプル id はクローズ/再オープンをまたいで有効（再オープン後に古い TID で Get できる）。
- [x] **エラー伝播（`fakePool`）:** Insert は `FetchPage` 失敗と `NewPage` 失敗を表面化する; Insert は想定外の（`ErrNoSpace` でない）ページエラーを「ページ満杯」と誤らず伝播する; Scan は `FetchPage` 失敗を表面化する。

## 2. B+Tree インデックス（`nbtree`）

key → `heap.TID` のマップ。インデックスファイル上に 1 ノード = 1 ページ（page 0 = meta、page 1 以降 = ノード）。v1: 唯一の `int64` key; Search / Insert(+分裂) / 範囲 Scan; 削除は延期。[B+Tree インデックス設計](../../design/access/BTree-Index-Design.ja.md) 参照。

### 2.1 ノードのバイトレイアウト（`nbtree_internal_test.go`、ホワイトボックス）

- [x] **容量がページに収まる:** 固定オフセット算術は、容量まで詰めた内部/葉ノードの全フィールドを 8192 バイト内に保つ; 第 2 配列のオフセットはヘッダー + keys の算術に等しい。
- [x] **Init:** `initLeaf`/`initInternal` はノード種別を設定し、空で始まり、前の占有者が残したバイトをゼロ化する。
- [x] **フィールドの往復:** key（負値含む — 生で格納し、デコードした `int64` で比較）、子ポインタ、TID（page + slot）、`next_leaf`。
- [x] **search:** 下限インデックスと found フラグ — 空ノード、完全一致、ミス、両境界。
- [x] **childIndex:** key を含む帯へ下降; separator に等しい key は右へ下降。
- [x] **full:** 両ノード種別で容量を報告する（1 つ手前では満杯でない）。
- [x] **insertLeafAt / insertInternalAt:** ソートされたシフトが key と並列の TID/子を揃えたまま保つ; separator の右子は `i+1`、`child[i]` は左のまま; 葉はページを溢れさせずに容量まで満ちる。
- [x] **splitLeaf:** エントリを均等に分ける; separator は右葉の先頭 key（copy-up — 葉に残る）。
- [x] **splitInternal:** 中央 key を押し上げ（両半分から除去）、子を key と一緒に分ける。

### 2.2 木の操作 — ホワイトボックス（`fakePool` + `smallCaps`）

- [x] **Insert/Search/Scan の往復:** シャッフルしたバッチが往復し、全走査は全 key を昇順で返す。極小容量が多数の葉分裂・内部分裂・複数段の root 成長を強制する。
- [x] **重複拒否:** 重複 key は `ErrDuplicateKey` を返し、最初の値を上書きしない。
- [x] **範囲走査:** `[lo, hi]` を守り、`next_leaf` で葉境界をまたぐ; 空範囲・単点範囲も処理。
- [x] **Scan の早期停止:** コールバックのエラーが走査を中断し伝播する。
- [x] **空の木:** Search は何も見つけず、Scan は何も訪れない。
- [x] **再オープン:** 非空で妥当なインデックスが再オープンでき、データが見える。

### 2.3 エラー経路 — ホワイトボックス（`fakePool`）

- [x] **ブートストラップ:** `NewPage` 失敗が meta ページと、別途 root 葉で表面化する。
- [x] **オープン:** 不正な magic を拒否; オープン時の meta 読み取りエラーが表面化する。
- [x] **meta 読み取り:** meta ページの fetch 失敗が Insert・Search・Scan から表面化する。
- [x] **ノード fetch:** meta ページより下の fetch 失敗が、下降（再帰 Insert）・Search・走査の連鎖の後続の葉（最初の葉は成功後）から表面化する。
- [x] **分裂の割り当て:** `NewPage` 失敗が各分裂地点 — 葉分裂・内部分裂・新 root 割り当て — で表面化し、root 分裂後の meta 更新失敗も表面化する。

### 2.4 統合 — ブラックボックス（`nbtree_test.go`、実プール、本番容量）

- [x] **追い出しを通した複数段:** 584 超の key が実容量で葉を分裂させ複数段の木を作る; プールがノード数より小さいと追い出し/再ロードを駆動する。全 key が読み戻り、全走査はソート済み。
- [x] **永続化:** インデックスはクローズ/再オープンをまたいで生存する — セッション 2 が meta magic を検証し、永続化された root を読み、セッション 1 が入れた全 key を見つける（未挿入の奇数 key は不在）。

## 実施順序

**heap:**

1. スキャフォールド: テストファイル、ヘルパー、`fakePool`。
2. Insert/Get の往復、次にページまたぎ。
3. Scan — 全訪問、次に早期停止。
4. エラー経路 — 実物（範囲外・大きすぎ・再オープン）とフェイク注入（fetch/new/想定外）。
5. 仕上げ: `make check`、`feat(heap): ...` でコミット。

**nbtree:**

1. ノードのバイトレイアウト + ノードレベルの操作（ホワイトボックス）: フィールド、search、insert、split。
2. `fakePool` + `smallCaps`; 分裂と複数段成長を強制した Insert/Search/Scan。
3. 範囲走査、重複、空の木、早期停止、再オープン。
4. エラー経路: ブートストラップ / オープン / meta 読み取り / ノード fetch / 分裂割り当て / meta 更新。
5. 実プール上のブラックボックス統合: 複数段 + 追い出し、次に永続化。
6. 仕上げ: `make check`、`feat(nbtree): ...` でコミット。
